## 2. 本轮已落地改动（5 个文件，待你审核后才算数）

### 2.1 新增 `scm-framework/.../config/json/ScmJsonMapperFactory.java`

**为什么**：B-1。让 HTTP 出站日期与升级前一致、入站宽容兼容旧新两种格式，并作为后续所有 mapper 的唯一来源（M-5）。

**内容**：
- `DATE_TIME_PATTERN = "yyyy-MM-dd HH:mm:ss"`、`DATE_PATTERN = "yyyy-MM-dd"`
- `mvcMapper()` / `mvcMapper(JsonInclude.Include)`：`defaultDateFormat` + `LocalDateTime`/`LocalDate` mixin（`@JsonFormat`）+ `SimpleModule` 注册两个宽松反序列化器
- `LenientLocalDateTimeDeserializer`：依次尝试 `LocalDateTime.parse(text.replace(' ','T'))` → `OffsetDateTime.parse` → `Instant.parse` → `LocalDate.atStartOfDay`，全失败抛 `IllegalArgumentException`
- `LenientDateDeserializer`：同上四种格式 → `java.util.Date`

**风险**：`SimpleDateFormat` 非线程安全，由 Jackson 内部 clone 使用（升级前也是同一机制）；`p.getValueAsString()` 对数字型日期（时间戳入参）返回非空但不可解析文本 → 会抛错，需在联调验证里覆盖。

### 2.2 `CallbackMappingJackson2HttpMessageConverter.java`

- 构造函数改为 `(JsonMapper)` 并可无参（走工厂）；`NON_NULL_MAPPER` 改用 `ScmJsonMapperFactory.mvcMapper(NON_NULL)`
- **新增 `canWrite` 重写**：`CharSequence` 一律返回 `false`，从根上避免 B-2 类问题
- 去掉 `changeDefaultVisibility(ALL, ANY)`（理由见 §4-D2-b：fastjson2 默认走 getter，Jackson 默认行为更接近，避免把无 getter 的 private 字段一起输出）

### 2.3 `ActionInterceptorConfig.java`

- 删除 `extendMessageConverters()` + `converters.add(0, …)` 写法
- 改为 `@Bean ServerHttpMessageConvertersCustomizer` → `builder.withJsonConverter(converter)`
- 好处：转换器占据「JSON 转换器」原生位置（在 `StringHttpMessageConverter` 之后），不需要算下标

### 2.4 `RestTemplateConfiguration.java`

- 出站显式复用 `ScmJsonMapperFactory.mvcMapper()`，保证调用第三方时的日期格式与入站同一口径（H-3）

### 2.5 `RedisCacheAutoConfiguration.java`

- 类型信息显式 `activateDefaultTyping(ptv, NON_FINAL, JsonTypeInfo.As.WRAPPER_ARRAY)` → 与旧值同格式，**可回滚**（H-5）
- 白名单收敛：`com.xinyirun.`、`java.util.`、`java.lang.`、`java.math.`、`java.time.` + `allowIfSubTypeIsArray()`（H-4）

**验证状态**：以上 5 个文件 **已通过编译**（BUILD SUCCESS），**未运行时验证**，**未评审**。
