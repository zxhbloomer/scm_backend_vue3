| 分支 | 升级前（fastjson2，HEAD 实码） | 现在（Jackson 3 实码） | 行为是否变化 | 生产端数量 |
|---|---|---|---|---|
| NORMAL(0)（`ResultUtil.OK(data)` 默认） | `WriteMapNullValue` + **`WriteNullBooleanAsFalse`** + PrettyFormat ⇒ null Boolean → `false` | `Include.ALWAYS`（`ScmJsonMapperFactory:49-51/64`）⇒ null Boolean → `null` | **是：全站** | 除下列 2 例外**全部接口**（`scm-bean/.../ResultUtil.java:61`、`ApiResultUtil.java:57`、`AppResultUtil.java:61`） |
| STRING_EMPTY_BOOLEAN_FALSE(1) | `WriteNullStringAsEmpty` + `WriteNullBooleanAsFalse` + PrettyFormat ⇒ null String → `""`、null Boolean → `false` | `Include.ALWAYS` ⇒ 两者都 → `null` | **是** | 2 处：`SystemAreaController.java:71`、`MasterMenuController.java:57` |
| NULL_NOT_OUT(2) | `ReferenceDetection` + PrettyFormat（不输出 null） | 专用 `NON_NULL` mapper（`Callback…:54,99-112`）⇒ 不输出 null | 否（等价） | 2 处：`UserController.java:64,81` |
| 全部 | `PrettyFormat` ⇒ 响应是**缩进多行** JSON | 无 pretty printer ⇒ **紧凑** JSON | 是（格式，非语义） | 全站；该项已登记于 `15:139`(D3)、`15:178`，**但 `05`/代码注释未提** |

严重程度判断：

| 结论 | 依据 |
|---|---|
| 方案"仅影响两个接口"的严重程度判断**不合理**——`WriteNullBooleanAsFalse` 属默认分支，`null → false` 的消失是**全站响应形状变化**（`git show HEAD:` 三分支实码 + `ScmJsonMapperFactory:49-51` 实证）；`15:42`(H-1, high) 已认定此事，但 `15:135`、`15:176`、`05:356`、代码注释 `:42-45` 仍在沿用错误影响面 ⇒ **同一错误在 4 处未回填** |
| 实际业务风险：**中低**（不是 high，也不是"仅两接口"） | 前端 JS 中 `null` 与 `false` 同为 falsy，`if (x)` / `Boolean(x)` 行为不变；风险集中在**严格比较**（`x === false`）、**TS 类型声明 `boolean` 收到 null**、以及 `STRING_EMPTY_BOOLEAN_FALSE` 的 `"" → null`（前端若做 `x.length`/`x.trim()` 会抛 TypeError）。这两点必须写进 §6 而不是"仅两接口" |
| 关键属性：差异**只影响 null 值**，`true/false` 正常值、数值、字符串、日期都不受影响（日期已由 `ScmJsonMapperFactory:63-68` 锁回 `yyyy-MM-dd HH:mm:ss`，与 fastjson2 一致） | `ScmJsonMapperFactory.java:37-41,63-68` |

建议（三选一，需用户/前端拍板，方案里必须给出选项而不是"待前端确认"一句）：

| 选项 | 动作 | 代价 |
|---|---|---|
| A（推荐，改动最小） | 保持现状，把"全站 null Boolean → null、PrettyFormat 取消"登记为**显式 API 行为变更**，通知前端与第三方调用方；仅对 `STRING_EMPTY_BOOLEAN_FALSE` 的 2 个 VO 字段加 `@JsonSerialize(nullsUsing=…)` 恢复 `""` | 2 个 VO 各改若干字段；`05:356` 的处置计划本来就是这个方向，需扩到"全站登记 + 2 VO 字段级修复" |
| B | 在 `ScmJsonMapperFactory` 加 `BeanSerializerModifier`，对 `Boolean` 属性 null 输出 `false`（恢复全站旧行为） | 全量 serializer 定制，回归面最大，需单测覆盖 |
| C | 不改代码，仅把差异升级为已知风险登记并加前端回归清单 | 零代码风险，但线上字段严格比较类前端逻辑可能静默变化 |

## 4. 一句话给实施方的结论
