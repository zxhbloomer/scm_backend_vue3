## 3. lead 结论 1「只作用于 bean 属性，不作用于 Map value，也不作用于集合元素」—— **需修正：对 `WriteNullStringAsEmpty` 不成立**

命令：`java -cp fastjson2-2.0.66.jar;out7 Probe7Reviewer`（样本：`List<String> ls`、`String[] as`、`Set<String> ss`、`Collection<String> cs`、`Map<String,String> ms`、`List<List<String>> lls`、`Map<String,List<String>> mls`、`List<Boolean> lb`、`Integer[] ai`、`Map<String,Boolean> mb`，各含 1 个 null）
输出原文（[B] STRING_EMPTY 档为关键列）：
```
[A] NORMAL
    {"ai":[null],"as":[null],"cs":[null],"lb":[null],"lls":[[null]],"lo":[null],"ls":[null],"mb":{"k":null},"mls":{"k":[null]},"ms":{"k":null},"ss":[null]}
[B] STRING_EMPTY
    {"ai":[null],"as":[""],"cs":[null],"lb":[null],"lls":[[null]],"lo":[null],"ls":[""],"mb":{},"mls":{"k":[null]},"ms":{},"ss":[null]}
[C] NULL_NOT_OUT
    {"ai":[null],"as":[null],"cs":[null],"lb":[null],"lls":[[null]],"lo":[null],"ls":[null],"mb":{},"mls":{"k":[null]},"ms":{},"ss":[null]}
```
事实：**`ls`（`List<String>`）与 `as`（`String[]`）的 null 元素在 [B] 档被写成 `""`**；而 `ss`(Set)、`cs`(Collection)、`lls`(嵌套 List)、`mls`(Map 内的 List)、`mb`/`ms`(Map value) 均不替换。
另用 `Probe6Reviewer` 交叉验证「容器内 bean 的属性仍然生效」：
```
[A] NORMAL  {"lbean":[{"b":false,"n":null,"s":null}],"mbean":{"k":{"b":false,"n":null,"s":null}},...}
[B] STRING_EMPTY {"lbean":[{"b":false,"s":""}],"mbean":{"k":{"b":false,"s":""}},...}
```
⇒ 规则准确表述应为：**`WriteNullBooleanAsFalse` / `WriteNullStringAsEmpty` 作用于「bean 属性」以及「`List<T>` / `T[]` 的元素位置」，不作用于 `Set`/`Collection`/嵌套容器/`Map` 的 value；`WriteNullBooleanAsFalse` 对 `List<Boolean>` 元素也不生效（fastjson2 内部按具体类型走不同 writer 路径，行为不对称）。**

**应改成什么**：§2.3:316 与 §9:465 的「不作用于集合元素」改为上述准确表述，并把 `le[0]` 由「集合元素」的代表降格为「`List<Boolean>` 元素」的代表。

## 4. lead 结论 3「唯一残留差异是 Map 内 null value」—— **需修正：还有第二条**

由第 3 节：STRING_EMPTY 档下 `List<String>` / `String[]` 的 null 元素，基准出 `""`。
Jackson 侧能做到什么？命令：`java -cp jackson-databind-3.1.7 ...;out8 Probe8Reviewer`
输出原文：
```
[1] 默认(ALWAYS)                 {"as":[null],"b":null,"lb":[null],"ls":[null],"ms":{"k":null},"n":null,"s":null,"ss":[null]}
[2] valueOnly NON_NULL          {"as":[null],"lb":[null],"ls":[null],"ms":{"k":null},"ss":[null]}
[3] value+content NON_NULL      {"as":[null],"lb":[null],"ls":[null],"ms":{},"ss":[null]}
[4] [3]+APPLY_..._CONTAINERS    {"as":[],"lb":[],"ls":[],"ms":{},"ss":[]}
[5] ALWAYS+content NON_NULL+sw  {"as":[],"b":null,"lb":[],"ls":[],"n":null,"s":null,"ss":[]}
```
⇒ 文档拟用的 `contentInclusion=NON_NULL`（[3]）确实解决了 **Map value**（`ms:{}` 与基准一致），且**不会误伤** List/数组元素（[3] 仍 `[null]`，此点是好消息）；但 Jackson **无法把元素写成 `""`**：不开全局开关是 `[null]`，开 `SerializationFeature.APPLY_JSON_INCLUDE_FOR_CONTAINERS` 是 `[]`（[4]/[5]），都不是 `[""]`。

**应改成什么**：§2.3:319「真正剩下的差异只有一条」→ 两条，第二条为「STRING_EMPTY 档 `List<String>`/`String[]` 的 null 元素：基准 `""`，Jackson 只能 `null` 或 `[]`」；§2.3:325 表「⚠️ 仅此一处需对齐」→ 两处；§2.3:326「List / 数组里的 null 元素 保留 ✅ 一致」需加限定「`List<String>`/`String[]` 在 STRING_EMPTY 档例外」；§8 `Probe4` 行结论「三档集合元素 null 均保留」需限定样本为 `List<Boolean>`；§9 第 1 条同步。

## 5. 该残差的实际影响面（今日无实际差异，但必须登记为边界）

## 6. §4 验收清单第 7 条 —— 需修正（抽样形状选错了）

原文：「含 `Map<String,Object>` / `List<Boolean>` 元素的接口 … 容器内 null 两边行为一致（都保留 null），不需 diff」。
**`List<Boolean>` 恰是唯一恒等的那一种**（Probe7 [B] `lb:[null]`）。若换成 `List<String>` 即不等。
