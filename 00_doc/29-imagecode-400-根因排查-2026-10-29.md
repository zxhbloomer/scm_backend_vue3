# 29 - `/api/v1/imagecode` 返回 400 根因排查（2026-10-29）

## 0. 一句话根因

**前端验证码 URL 把查询串写成了 `?=<随机数>`（参数名为空），Tomcat 11 对「以 `=` 开头的参数块」直接抛 `InvalidParameterException` 并返回 400；Tomcat 10 只是 DEBUG 忽略。属升级引入的行为回归，不是后端业务代码问题。**

证据等级：**已隔离复现**（裸 Tomcat 11.0.27 / 10.1.46 对照，无 Spring），**非推断**。

## 1. 现象

| 项 | 内容 |
|---|---|
| 触发 | 打开前端登录页（DevTools Console） |
| 请求 | `GET http://localhost:9528/scm/api/v1/imagecode?=0.17949192386470236` |
| 结果 | `400 (Bad Request)`，验证码图片不显示 |
| 后端日志 | 只有一条 `DispatcherServlet : "ERROR" dispatch for GET "/scm/error?=0.179…"`，`BasicErrorController` 输出 `status=400, path=/scm/api/v1/imagecode` |
| 后端日志特征 | **无任何异常堆栈**；`SysCaptchaController` 无一行日志（方法根本没进） |

## 2. 根因链（逐层取证）

| 层 | 事实 | 证据来源 |
|---|---|---|
| 前端 | `src/views/login/index.vue:320`：`this.codeImg = \`${import.meta.env.VITE_BASE_API}/api/v1/imagecode?=${Math.random()}\`` | 读源码（前端仓库 `D:\2026_project\00_scm\frontend\scm_frontend`） |
| 前缀 | `.env.development:5` `VITE_BASE_API = '/scm'` ⇒ 最终 URL `/scm/api/v1/imagecode?=0.179…` | 读 `.env*` |
| 容器 | Tomcat 11.0.27 `Parameters.processParameters`（`Parameters.java:378`）抛 `InvalidParameterException: Invalid chunk starting at byte [0] and ending at byte [1] with a value of [=] ignored` | 裸 Tomcat 复现的异常堆栈 |
| 版本 | 项目 Tomcat = **11.0.27**（Spring Boot 4.1.2 带）；升级前 Spring Boot 3.5 为 Tomcat 10.1.x | jar 内 `tomcat-embed-core-11.0.27.jar` |

## 3. 隔离复现矩阵（裸 Tomcat，无 Spring、无本项目代码）

| 请求 | Tomcat 11.0.27 | Tomcat 10.1.46 |
|---|---|---|
| `?=`             | **400**（InvalidParameterException） | 200 |
| `?=abc`          | **400** | — |
| `?=0.17`         | **400** | 200 |
| `?a=`            | 200 | 200 |
| 无参数            | 200 | 200 |

对运行中应用的实测（同一结论，与路径无关）：

| 请求 | 结果 |
|---|---|
| `/scm/api/v1/imagecode?=0.179…` | 400 |
| `/scm/actuator/health?=1` | 400 |
| `/scm/nonexistent-xyz?=1` | 400 |
| `/scm/actuator/health` | 200 |

⇒ 只要是「空参数名」一律 400，是容器级行为，与具体接口、鉴权、拦截器都无关。

## 4. 已排除的假设

| 假设 | 排除依据 |
|---|---|
| Spring Security `StrictHttpFirewall` 拦截 | `javap` 反编译 7.1.2 的 `StrictHttpFirewall`，**不读取 `getQueryString()`**（命中 0 次） |
| 后端拦截器/多租户/鉴权抛错 | 日志无异常堆栈；`parameters={}`；控制器方法未进入 |
| fastjson2/Jackson 序列化问题 | 请求根本没到 `DispatcherServlet` 的业务分发 |
| 参数解析 `parameters.noequal` 之类"忽略"逻辑 | 该分支只打 DEBUG；实际抛出的是 `parameters.invalidChunk` 对应的 `InvalidParameterException`（Tomcat 11 改为抛异常） |

## 5. 影响面

| 范围 | 影响 |
|---|---|
| 登录页验证码 | **直接不可用**（图片 400） |
| 其它前端请求 | 只要不带空参数名，均不受影响；全仓扫描 `?=${` 仅此 1 处 |
| 后端代码 | 无需改动（后端无错） |
| 生产环境 | 同样会中招（Tomcat 11 是 Boot 4.1.2 默认），升级上线前必须修前端 |

## 6. 方案（待批准，未改任何代码）

| 方案 | 改动 | 评价 |
|---|---|---|
| **A（推荐）** 前端改 1 个字符 | `src/views/login/index.vue:320`：`?=${Math.random()}` → `?_=${Math.random()}` | 一行、零风险、语义正确（`_` 为常用缓存穿透占位参数名）；同时 `?=` → `?_=` |
| B 前端改用时间戳 | 同处改 `?_=${Date.now()}` | 与 A 等价，可选 |
| C 后端兜底 | 在过滤器中重写 queryString 去掉空名参数 | **不推荐**：参数解析发生在 DispatcherServlet 早期，过滤器包裹不可靠；且为前端缺陷在后端加补丁违反 KISS |
| D 降级容器 | 回退 Tomcat 10.x | 不可行（Boot 4.1.2 要求 Tomcat 11） |

**建议：只做 A。** 若同一前端还有其它"手拼 `?` + 随机数"的写法，需一并扫（本次全仓仅发现 1 处）。
