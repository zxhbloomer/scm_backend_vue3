## 二、构建层评审（采纳）

### Blocker
1. **`pom.xml:58` 升 4.1.2 会立刻炸** —— 该属性是 14 处依赖管理的版本来源，其中 `pom.xml:126` 的 `spring-boot-starter-aop` 在 Boot 4 不存在（4.1.2→404；本地仓库该 artifact 最高 3.5.5 + 4.0.0-M2；`-aspectj` 有 4.1.2）。
   **我的复核**：✅ 全对。声明点仅 `pom.xml:126` + `scm-common/pom.xml:60`。
2. **"换完 boot4-starter 后 `mybatis-spring 3.0.5` 自然失效"是 Maven 语义错误** —— 消费端 `dependencyManagement` 永远优先于传递依赖。

### High
- **"纯 Jackson 3"前提不成立**：springdoc 3.2.0 经 swagger-core 自带 Jackson 2.21.7，而 Boot 4.1.2 BOM 亲自托管该版本 ⇒ 共存安全。**口径改为"业务代码零 Jackson 2 import + 被动共存"**。
- **`HikariCP 5.0.1`@823 压住 BOM 7.0.2**（我复核：BOM 实测 `<hikaricp.version>7.0.2`）。
- **清钉不能"先换再删"**：中间态必 `NoSuchMethodError`（MP starter 按 mybatis-spring 4.1.0 编译）/ 类不匹配（druid starter 1.2.28 vs 核心 1.2.20）⇒ 改 3 个原子扇区。
- **`surefire 2.19.1`@988 + `skipTests`@991**：Boot 4.1.2 是 JUnit 6.0.3，surefire 2.19.1 跑不了 ⇒ 升级后 `mvn test` 静默跑 0 用例，"构建通过"是假信号。**已提为 P0**。
- **`spring-retry 2.0.3`@174**：BOM 命中 0 行（我复核确认），无兜底，`@EnableRetry` 在用。

### Medium / Low（已并入 02 的 P2 补充表）
- `spring-restdocs-mockmvc` **代码 0 引用**（我复核全仓 `import org.springframework.restdocs` = 0 文件）⇒ 直接删 6 处，不做 2.0.5→4.0.2 迁移。
- 文档把 `springdoc-openapi-starter-webmvc-ui` 误写成 `springdoc-openapi-inflector`（该坐标不存在）。
- 漏钉：`commons-pool2 2.11.1`、`javassist 3.23.1-GA`、`maven-jar-plugin 2.4`、`fastexcel 1.2.0`、`poi 5.2.4`、死坐标 `org.mybatis.spring.boot:mybatis-plus-spring-boot3-starter`@340-344、`spring-plugin-core`/`commons-text 1.6`（CVE-2022-42889）/`jsoup 1.13.1` 等 12 条死钉。
- `aop → aspectj` **等价可 1:1 替换**（依赖树成分相同：starter + spring-aop + aspectjweaver 1.9.25.1，代码零改动）。

## 四、AI 线评审（主体采纳，数字需修正）

### 采纳的 blocker
1. **`OpenAiApi` 在 spring-ai 2.0.1 整体删除**
   - **我的复核**：解包 `spring-ai-openai-2.0.1.jar`（79 条目）→ `org/springframework/ai/openai/api/` **0 条**、`OpenAiApi` **0 命中**；`AiModelProvider.java:201-214` 确实是 `OpenAiApi.builder()` + `.openAiApi()` + `.defaultOptions(OpenAiChatOptions.builder()…build())` ⇒ **重写级**，换官方 `com.openai:openai-java` SDK。
2. **MCP 注解包搬家 + SDK 跨大版本**
   - 1.1.3 注解来自 `org.springaicommunity:mcp-annotations:0.8.0`；2.0.1 迁入 `org.springframework.ai.mcp.annotation`。
   - **我的复核（与评审不一致）**：实测 **7 个工具文件 / 26 个 `@McpTool` + 82 个 `@McpToolParam` = 108 处**，8 个文件含 import。评审报 "116 + 83 = 199"，**高估约一倍**，故该项工作量按 108 处估。
   - SDK：`pom.xml:81` 钉 `mcp.sdk.version=0.16.0` → 2.0.1 要 `io.modelcontextprotocol.sdk:mcp:2.0.0`；`scm-ai/pom.xml:84-97` 的降版本排除 hack 必须删。
3. **`scm-ai` 必须先摘出构建**（`scm-start/pom.xml:114` 直接依赖；`spring-ai-commons-2.0.1` 要求 Boot 4.1.1 + `spring-context 7.0.9`，与 3.5.5 不共存）。
   - 补充硬阻塞（我方核出）：`scm-mq-consumer/pom.xml:66` 也依赖 `scm-ai`，其下 3 个 consumer 共 5 处 import AI 实现类。

### 采纳的 High
- ChatClient / ChatOptions **Builder 化**（`defaultOptions` 只收 `ChatOptions.Builder`，`.build()` 要去掉）。
- 多 provider 走 OpenAI 兼容端点（SiliconFlow / DeepSeek / Moonshot / 智谱）在官方 SDK 下是最高运行时风险 ⇒ 验收要"每家 provider 至少 1 次真实联调 + 1 次流式 + 1 次 tool call"。
- Jackson 2/3 双栈（`spring-ai-commons-2.0.1` 用 Jackson 3；`argi-graph-core` 仍引 Jackson 2；`scm-ai` 内 22 行 Jackson 2 import）⇒ 需定 ObjectMapper 边界规则。
- **WorkflowEngine 的 checkpoint 历史兼容**：ARGI 的 `CompiledGraph` 与 SAA 签名基本一致（仅新增 `updateState(..., VersionedCheckpointScope)`），编译风险低，但"生产 checkpoint 数据能否被新序列化器读回"是上线前必测项（人机协同中断恢复依赖它）。

### 采纳的 Medium / Low
- Milvus 继续用 Spring AI 官方 `spring-ai-starter-vector-store-milvus:2.0.1`（ARGI 无 milvus）；`milvus-sdk-java` 升 2.6.21；`MilvusVectorStore$Builder` 1.1.3↔2.0.1 兼容（仅新增 `partitionName`）。
- `scm-ai/pom.xml` 只需改版本 + 唯一 graph 坐标，不用重写结构。
- `EmbeddingModel` / `FunctionToolCallback` / `ToolCallbackProvider` / `MessageChatMemoryAdvisor` 签名未变 ⇒ 自研 `SiliconFlowEmbeddingModel`、`McpToolConfig` 适配器不用改。

### 需要修正的说法
- **"SAA 已停更"是事实错误**：`spring-ai-alibaba-graph-core` 有到 `2.0.0-M1.1`（2026-09-16，对 spring-ai 2.0.0-M1）。准确表述："SAA 尚无基于 spring-ai 2.0.1（GA）的发布"。
- **"graph-core 只有 2 个文件"准确，但不能用来论证"AI 线便宜"**：graph 维度 = 2 文件 / 6 import 行；而 Spring AI 版本变更影响 **36 文件 / 12968 行（模块 30%）**。
