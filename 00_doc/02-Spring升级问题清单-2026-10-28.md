## 执行顺序（不可按"先升版本再清钉"做）

Maven 依赖调解规则：**消费端 `dependencyManagement` 优先于传递依赖，其次最近者优先**。因此"换 starter 家族 → 再删钉"会存在自相矛盾的中间态：

| 中间态 | 实际生效 | 后果 |
|---|---|---|
| MP 换 boot4-starter，留 `mybatis-spring:3.0.5` | 3.5.18 starter + mybatis-spring 3.0.5 | `NoSuchMethodError`（starter 按 4.1.0 编译） |
| druid 换 boot-4-starter，留 `druid:1.2.20` | starter 1.2.28 + 核心 1.2.20 | 类不匹配 |

**改为 3 个各自闭合、各自能 `clean install` 通过的原子扇区：**

| 扇区 | 内容 | 完成判据 |
|---|---|---|
| **前置**（必须先做） | `spring-boot-starter-aop → -aspectj`（`pom.xml:126` + `scm-common:60`，各删 version）；`pom.xml:58` 升 4.1.2 | 全仓 `mvn -T 1C clean install -DskipTests` 通过 |
| **A · 数据访问** | MP starter（`pom.xml:315-319` + 8 模块）+ **同一步删 `mybatis-spring` 钉（`:345-349`）** + druid starter（`:675`）+ **druid 核心 1.2.20→1.2.28（`:213`）** + dynamic-datasource starter（`:664`）+ 删死坐标（`:340-344`） | 数据源/多租户上下文启动通过 |
| **B · 平台基础** | quartz 删钉（`:423-427`）、spring-data-redis/commons 删钉、spring-session（`:56`）、mysql 坐标、lombok、hibernate-validator、HikariCP（`:823`）、commons-pool2、spring-retry、surefire/jar 插件删版本 | `mvn clean install -DskipTests` + `mvn test` 真跑出用例 |
| **C · Jackson** | Jackson 3 迁移 16 文件、SDR/AMQP 序列化器改名、jjwt→gson、fastjson2 2.0.66、`scm-core-clickhouse` 删显式 jackson-databind | 序列化回归用例 |

## 存量数据缺陷（与本次升级无关，但升级窗口必须处理）

`scm_tenant_20250519_001` 的 `ACT_RU_VARIABLE` 变量分布：`serializable 1654 / string 1256 / integer 428 / bpmnParallelMultiInstanceCompleted 420`。

这 1654 条 serializable 变量是 Java 序列化二进制。**实测其中 144 条**的类名是改包名前的老 FQCN com.xinyirun.wms.*（不是 1654 条全部，此前的 1654 口径有误，2026-10-28 已更正）：

```
java.lang.ClassNotFoundException: com.xinyirun.wms.bean.bpm.vo.form.Form
```

而当前仓库里的类是 `com.xinyirun.scm.bean.bpm.vo.form.Form`（`scm-bean/.../bpm/vo/form/Form.java`，`serialVersionUID = -45475579271153023L`）。

**结论：这批在途实例（最早 2024-12 的任务至今仍挂在 ACT_RU）的表单变量在现网 7.1.0 上也读不出来，与 Spring 4.1 / Flowable 8 无关。** 反向证据：`flowable-variable-service-8.0.0.jar` 里 `SerializableType.class` 仍在，Flowable 8 没有删除老变量机制。

备选处理（**待负责人决策**）：

| 方案 | 做法 | 代价 |
|---|---|---|
| a 归档清理（若业务已不需要这些历史单据） | 老实例/任务迁归档表，不再尝试读变量 | 最小，需业务确认 |
| b `resolveClass` 兼容 shim | `ObjectInputStream.resolveClass` 把 `com.xinyirun.wms.*` 映射到 `com.xinyirun.scm.*` | 中等，能救回大部分历史单据 |
| c 变量转 JSON | 一次性把 serializable 转 `json` 类型 | 最大，且需先能读出旧对象（回到 b） |

⚠️ 硬约束：升级期**不得修改 `Form` / `FormPerm` / `ValueType` 的字段**，否则连现在能读的实例也会 `InvalidClassException`。

## 追加（2026-10-28，B5 实测）：HTTP 序列化器注册方式在 Framework 7 变了 —— 不是格式问题，是启动阻断

### 实测结论（lead 亲自跑，证据在 `D:\temp\boot355-probe\probe355.log`、`D:\temp\flowable8-probe\conv-probe.log`）

| 项 | Boot 3.5.5 / Framework 6.2 | Boot 4.1.2 / Framework 7.0.10 |
|---|---|---|
| `configureMessageConverters(List)` 传入的 List 初始 size | **9**（预填，含 2 个 `MappingJackson2HttpMessageConverter`） | **0**（空） |
| `converters.add(4, fastjson2Converter)` | 成功，fastjson2 落在 index 4，排在 Jackson 之前 | **抛 `IndexOutOfBoundsException: Index: 4, Size: 0`** |
| 后果 | 正常启动，响应由 fastjson2 序列化 | **上下文启动失败**：`mvcContentNegotiationManager` → `Index: 4, Size: 0`，应用起不来 |
| 方法状态（`spring-webmvc-7.0.10-sources.jar` 实读） | 正常 | `configureMessageConverters(List)` 与 `extendMessageConverters(List)` 均 `@Deprecated(since="7.0", forRemoval=true)`；新增入口 `configureMessageConverters(HttpMessageConverters.ServerBuilder)` |

`HttpMessageConverters.Builder`（javap 实读）可用 API：`withJsonConverter(converter)`、`addCustomConverter(...)`、`configureMessageConvertersList(Consumer<List<...>>)`、`registerDefaults()`、`disableDefaults()`。

### 今天前端到底看到什么格式（生产真相）
`scm-framework/.../spring/ActionInterceptorConfig.java:67-71` 在 index 4 插入 `CallbackMappingJackson2HttpMessageConverter`（`extends FastJsonHttpMessageConverter`，`scm-framework/.../config/messageconverter/CallbackMappingJackson2HttpMessageConverter.java:68`），把 Jackson 挤到后面 → **今天的 HTTP 响应是 fastjson2 格式**（全仓库仅此一处注册，grep 已确认）。

同一 payload 各引擎输出（探针实测，普通 POJO 载体）：

- **fastjson2 2.0.66（= 今天的生产格式）**：`{"date":"2026-10-28 15:42:28","ldt":"2026-10-28 15:42:28","ld":"2026-10-28","instant":"2026-10-28T07:42:28Z","dur":"PT1M30S"}`
- **Jackson 3 默认（= 若不动 HTTP 层）**：`{"date":"2026-10-28T07:42:28.000Z","ldt":"2026-10-28T15:42:28","ld":"2026-10-28","instant":"2026-10-28T07:42:28Z","dur":"PT1M30S"}`
- **Jackson 2 默认（参考，非生产）**：`{"ldt":[2026,10,28,15,42,28],"date":1793173348000,"instant":1793173348.000000000,"dur":90.000000000}`

→ 工程含义：**前端是否要改，不取决于"Jackson 3 默认变了"这条一般性说法，取决于 HTTP 层最终选 fastjson2 还是 Jackson 3。** 选 fastjson2 = 前端零改动；选 Jackson 3 = 日期格式全站变（`Date` 从本地时间变 UTC+毫秒，`Date`/`LocalDateTime` 从 `空格` 变 `T`），前端必须改。

> 自我更正：`04`/`05` 里 B5 原表述「Jackson 3 默认日期从时间戳变 ISO-8601，前端不改就全站日期显示异常」**口径不准**——本项目今天不是 Jackson 在写响应，不存在"从时间戳变 ISO"；真实风险是「HTTP 层若换成 Jackson 3，格式从 `yyyy-MM-dd HH:mm:ss` 变 ISO-8601」。

## 追加（2026-10-28 二次）：D7 选 B（用 Jackson 3 替代 fastjson2 出响应）的可行性实证

### 用户决策
用户明确：`不要fastjson`（HTTP 层），走 Jackson 3。→ D7 = **方案 B'（Jackson 3 全局复刻 fastjson2 语义，前端零改动）**

### 探针实证（Boot 4.1.2 + Jackson 3.1.7 + fastjson2 2.0.66，`D:\temp\flowable8-probe`）

同一 POJO（Long 雪花 ID / BigDecimal / null String / null List / LocalDateTime / LocalDate / java.util.Date / Instant / enum）：

| 口径 | 输出 |
|---|---|
| fastjson2（= 今天生产格式） | `{"amount":1234.50,"date":"2026-10-28 15:42:28","id":1793173348123456789,"instant":"2026-10-28T07:42:28Z","ld":"2026-10-28","ldt":"2026-10-28 15:42:28","name":"测试"}` |
| Jackson 3 **默认** | `…"date":"2026-10-28T07:42:28.000Z"…"ldt":"2026-10-28T15:42:28"…` + `"nul":null,"tags":null` |
| Jackson 3 **全局配置后**（SimpleModule + `defaultTimeZone(Asia/Shanghai)` + `defaultDateFormat("yyyy-MM-dd HH:mm:ss")`） | `{"amount":1234.50,"date":"2026-10-28 15:42:28","id":1793173348123456789,"instant":"2026-10-28T07:42:28Z","ld":"2026-10-28","ldt":"2026-10-28 15:42:28","name":"测试","nul":null,"tags":null}` |

| fastjson2 行为 | 原文位置 | 使用范围（grep 实测） | Jackson 3 对策 | 需写代码 |
|---|---|---|---|---|
| 默认分支：`ReferenceDetection`+`WriteMapNullValue`+`WriteNullBooleanAsFalse`+`PrettyFormat` | L131-139 | 全部响应 | null 输出=默认；缩进=`spring.jackson.serialization.indent-output=true`；`ReferenceDetection` **无等价物**（见风险） | 否（配置）/ 风险项需评估 |
| `STRING_EMPTY_BOOLEAN_FALSE`：null String→`""`、null Boolean→`false` | L107-111 | `MasterMenuController.java:57`、`SystemAreaController.java:71`（**仅 2 处**） | Jackson 无内置 null→""/false（社区确认需自定义 `BeanSerializerModifier`/NULL provider）→ 也可在这 2 个 VO 字段上处理 | 是（局部） |

| POC-4b | `@JSONField(serialize=false)` 在 Jackson 3 下是否生效 | Jackson 3 输出 `{"hidden":["secret"],"keep":"k"}` —— **完全无效**；fastjson2 正常排除 | ⚠️ 不能靠 `@JSONField` 控制 Jackson 输出 |
| POC-4c | `tools.jackson` 的 `@JsonNaming(SnakeCase)` 能否一劳永逸 | Jackson 3 写读都下划线 ✅；**fastjson2 不认**，输出驼峰 ❌ | ❌ **否决类级命名策略路线**，只能逐字段 `@JsonProperty` |
| POC-4d | 无注解时 Jackson 3 读下划线键 | `{"user_inputs":"U","userInputs":"CAMEL"}` → 绑成 `CAMEL`，下划线键**静默丢弃** | ⚠️ 驼峰字段 + 前端发下划线键的 `@RequestBody` DTO 会静默丢参；全仓 `@JsonNaming` 0 处、`@JsonProperty` 13 文件，契约靠 Java 字段名本身承载 → 现存风险面为 0 |
| POC-5 | Boot 4.1.2 classpath 里有没有 `com.fasterxml.jackson.databind` | 编译报错实证：**不存在**（只有 `com.fasterxml.jackson.core:jackson-annotations` 2.x） | ❗迁移后**禁止** import `com.fasterxml.jackson.databind.*`；`@JsonNaming`/`PropertyNamingStrategies` 只存在于 `tools.jackson.databind` |

### 13.1 由此确认的唯一真实破坏点

`scm-bean/src/main/java/com/xinyirun/scm/bean/system/ao/fs/UploadFileResultAo.java:26-27`：字段名 `fileUuid`，靠 `@JSONField(name="fileId")` 改名；该类被 **7 个响应 VO 继承**（`BCarriageOrderDetailVo`、`BMonitorSumVo`、`BMonitorVo`、`BReturnRelationVo`、`BReturnRelationBackupV2Vo`、`SDictTypeVo`、`SRoleVo`）。前端 `frontend/scm_frontend/src/components/70_ai/components/chat/input/ChatInputWrap.vue:668` 读 `response.data.fileId`。

D7=B'（Jackson 3 出响应）后该字段名变 `fileUuid` → **AI 聊天上传附件功能断**。修法：**这 1 个字段改 `@JsonProperty("fileId")`**（POC-2 已证 fastjson2 也认），前端 0 改动；`file_size`、`internal_url` 本身就是下划线字段名，天然一致，无需处理。

日期同类：`AiWorkflowRuntimeVo.java:68` 的 `@JSONField(format="yyyy-MM-dd HH:mm:ss")` 在 Jackson 3 下会输出 ISO → 需补 `@JsonFormat(pattern=...)`（注解仍在 `com.fasterxml.jackson.annotation`，Boot 4 保留，全仓已有 11 处先例）。

### 13.2 §12.3 三项 POC 的关闭情况

① `JSONObject` 绑定 → POC-1 通过；② fastjson2 认 `@JsonProperty` → POC-2 通过；③ `scm-excel` 6 处 `serialize=false` → POC-4b 证明注解对 Jackson 无效，但这 6 个类只经 `JSON.parseObject(jsonConfig, ...)` 走 fastjson2、无 Jackson 出口，判定**不需要改**。

### 13.3 补充实证（POC-6）：fastjson2 与 Jackson 3 一样"严格按字段名绑定"，不存在智能匹配差异

| 场景 | fastjson2 2.0.66 实测 | Jackson 3.1.7 实测（POC-4d） |
|---|---|---|
| 下划线键 `user_inputs` → 驼峰字段 `userInputs` | **null（不绑定）** | 不绑定（静默丢弃） |
| 驼峰键 `userInputs` → 驼峰字段 | `CAMEL` ✅ | `CAMEL` ✅ |
| 驼峰键 `userInputs` → 下划线字段 `user_inputs` | **null（不绑定）** | — |

**意义**：两个引擎都不做下划线/驼峰互转（fastjson2 的 `SupportSmartMatch` 默认关闭），所以"换 Jackson 3 会因命名匹配差异静默丢参"这一类风险**不存在**。现存 HTTP 契约完全由 Java 字段名 + 显式注解承载，一一对应，无隐藏映射。
