## 1. 背景与问题

### 1.1 直接触发点（实测，非推测）

Boot 3.5.5 → 4.1.2 升级后第 3 次启动尝试（日志 `D:\temp\20261028\新建 文本文档 (4).txt`，8655 行）：

```
Parameter 0 of constructor in com.xinyirun.scm.ai.core.service.KnowledgeBaseService
required a bean of type 'com.fasterxml.jackson.databind.ObjectMapper' that could not be found.
```

调用链：`documentController → documentProcessingService → knowledgeBaseService`。

**根因**：Boot 4 只自动配置 Jackson 3 的 `tools.jackson.databind.json.JsonMapper`，**不再提供 `com.fasterxml.jackson.databind.ObjectMapper` bean**（Jackson 2 自动配置已废弃）。项目代码里 15 个文件仍在使用 Jackson 2 的 `ObjectMapper` 类型，其中按字段注入的那一处直接把应用启动打断。

### 1.2 为什么不能"把 Jackson 2 留着就行"

Jackson 2 在依赖树中有 **6 条来源**（`mvn dependency:tree` + `jdeps` 实测）：

| 来源 | 是否我方可控 | 建议 |
|---|---|---|
| Flowable 8.0.0（`flowable-engine-common` 等） | 否 | 保留（Flowable 8 双栈：Jackson 3 默认 + Jackson 2 兼容层） |
| Spring AI 2.0.2 / ARGI | 否 | 保留 |
| springdoc-openapi 3.2.0 | 否 | 保留 |
| clickhouse-jdbc | **是**（项目额外多声明了一次） | 删除冗余声明（见 REQ-J-11） |
| jjwt-gson（已从 jjwt-jackson 切换） | 是 | 已解决 |
| 项目自身 15 个文件的 import | **是** | **本需求主体** |

结论：**Jackson 2 的 jar 会继续留在 classpath（第三方依赖需要），但项目自己不再写 Jackson 2 代码**；两者不冲突，只要不混用同一个 mapper 实例。

## 2. 目标与非目标

### 2.1 目标
- G1：应用在 Boot 4.1.2 下**启动成功**（消除 `ObjectMapper` bean 缺失类错误）。
- G2：项目自有代码**零 Jackson 2 数据绑定 API import**（`com.fasterxml.jackson.databind.*` / `com.fasterxml.jackson.core.*` / `com.fasterxml.jackson.datatype.*`）。
- G3：**HTTP 响应 JSON 契约不变**（字段名、日期格式、null 策略、`@JsonProperty/@JsonFormat` 注解全部沿用）。
- G4：Redis 缓存与 JWT 解析链路行为不变。

### 2.2 非目标
- N1：不处理 fastjson2 → Jackson 3 的业务层迁移（413 处，独立扇区 S2 之后的议题）。
- N2：不删除第三方依赖带来的 Jackson 2 jar（Flowable/Spring AI/springdoc 需要）。
- N3：不改变前端契约、不调整日期格式策略（沿用当前项目既定口径）。
- N4：不改 `ScheduleConfig`（另有待决策项，见 §9）。

## 4. 功能需求

| 编号 | 需求 | 验收方式 |
|---|---|---|
| **REQ-J-01** | 项目自有代码不得 import `com.fasterxml.jackson.databind.*` / `com.fasterxml.jackson.core.*` / `com.fasterxml.jackson.datatype.*`（`com.fasterxml.jackson.annotation.*` 允许） | `Select-String -Pattern 'import com\.fasterxml\.jackson\.(databind|core|datatype)'` 结果为空（排除未构建模块 `scm-core-whapp`） |
| **REQ-J-02** | 所有 `ObjectMapper` 获取途径改为「容器注入」或「`JsonMapper.builder()` 构建的静态单例」，禁止在方法体内 `new ObjectMapper()` | 代码评审 + `grep 'new ObjectMapper'` 为空 |
| **REQ-J-03** | `JsonUtil` 作为项目统一 JSON 工具，须保持对外方法签名与行为兼容（含 `TypeReference` 重载、`JsonNode` 返回类型） | 编译通过 + 调用方零改动（除 import） |
| **REQ-J-04** | `JsonUtil` / `RedisCacheAutoConfiguration` 删除 `JavaTimeModule` / `Jdk8Module` 注册（Jackson 3 内建） | 编译通过 + 冒烟：`LocalDateTime`/`Optional` 序列化正常 |
| **REQ-J-05** | Redis 序列化器由 `Jackson2JsonRedisSerializer` 改为 `JacksonJsonRedisSerializer`；**存量缓存数据兼容方案必须显式给出**（见 REQ-J-06） | 启动无 `SerializationException` |
| **REQ-J-06** | 存量 Redis 数据处置二选一并在文档中记录：(a) 升级窗口内清空本项目相关缓存；(b) 过渡期双读（`GenericJackson2JsonRedisSerializer` 读老 key，新写入用 Jackson 3） | 实施记录在 `05-代码变更登记册` |
| **REQ-J-07** | `RestTemplateConfiguration` 的 JSON 转换器切换到 `JacksonJsonHttpMessageConverter`，并保留原有 `FAIL_ON_EMPTY_BEANS=false` 语义 | 冒烟：外部 HTTP 调用（含空 bean 序列化）不抛异常 |
| **REQ-J-08** | 4 个 `JsonParser` 使用点（JWT 过滤器 ×2、SsoLoginFilter、JsonUtil）改用 `tools.jackson.core.JsonParser`，解析逻辑不变 | 冒烟：登录 / 鉴权 / SSO 三条链路可用 |
| **REQ-J-09** | 异常处理：`catch (JsonProcessingException)` 全部改为 `catch (JacksonException)`；**不得**用 `catch (Exception)` 泛化替代 | `grep 'JsonProcessingException'` 为空 |
| **REQ-J-10** | 对外 HTTP JSON 契约不变：字段名、`@JsonFormat` 日期格式、null 输出策略与升级前一致 | 抓包/单测对比：登录响应、分页列表、BPM 审批详情三个接口的 JSON 结构逐字段一致 |
| **REQ-J-11** | 删除 clickhouse 相关的 Jackson 2 冗余显式声明（保留其传递依赖即可） | `mvn dependency:tree -Dincludes=com.fasterxml.jackson.core` 中不再出现我方直接声明 |
| **REQ-J-12** | 本轮改动全部登记到 `05-代码变更登记册` 与 `06-按文件修改清单`（含文件名、行级要点、原因、验证结果） | 文档 diff 可见 |

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-1 | 性能 | mapper 全局单例复用；不得在热路径（过滤器、转换器、工具方法）中重复构建 mapper |
| NFR-2 | 性能 | 升级后单次 JSON 序列化耗时不得劣化超过 20%（抽样 3 个典型响应对象，各 1 万次取均值） |
| NFR-3 | 安全 | 不得为兼容而开启 Jackson 2 的 `DefaultTyping`；Jackson 3 侧禁止开启 `@class` 式多态反序列化白名单扩大 |
| NFR-4 | 兼容 | 保留一条**回退开关**：必要时可加 `spring-boot-jackson2` 依赖 + `spring.http.converters.preferred-json-mapper=jackson2` 临时回到 Jackson 2 映射器（仅过渡，需在文档中标注为技术债） |
| NFR-5 | 可维护 | 不引入 `ObjectMapper` 的"每处一套配置"；统一由 `JsonUtil` 或注入的 bean 提供 |

## 8. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| R1 响应日期格式变化（若某处 mapper 由 builder 新建且未继承 Boot 配置） | 前端显示异常 | 优先注入 Boot 的 `ObjectMapper` bean；自建 mapper 时显式对齐 `DateTimeFeature` |
| R2 存量 Redis 数据反序列化失败 | 缓存穿透/报错 | REQ-J-06 的双读策略或清空窗口 |
| R3 `JacksonException` unchecked 化导致异常被吞 | 静默失败 | 代码评审重点检查 catch 块；关键链路加日志 |
| R4 Flowable / Spring AI 内部 Jackson 2 与项目 Jackson 3 混用 | 运行期反序列化为空 | 严禁跨栈传递同一对象；边界处只传 String/byte[] |
| **回退** | — | 加 `spring-boot-jackson2` 依赖 + `spring.http.converters.preferred-json-mapper=jackson2`，并把 15 个文件改回原状（保留 git 分支即可秒回） |

## 9. 前置依赖与未决项

1. **`ScheduleConfig` 方案未定**（`00_doc/10` 报告，方案 1「独立连接池 + 补 DataSourceProperties bean」vs 方案 3「复用主数据源」）。**该问题与本需求相互独立**，但同属"应用能启动"的前置条件，建议一并拍板。
2. **Jackson 2 是否彻底清零**：Flowable 8 / Spring AI 2.0.2 / springdoc 3.2.0 会继续带 Jackson 2 jar（不可控），本需求只保证"项目自有代码清零"。
3. **fastjson2 与 Jackson 3 并存的最终形态**：本项目 HTTP 出口目前仍是 fastjson2 转换器（`CallbackMappingJackson2HttpMessageConverter`），Jackson 3 迁移完成后会出现"三栈并存"（fastjson2 / Jackson 3 / 第三方 Jackson 2）。**是否在本次一并把 HTTP 出口切到 Jackson 3，需用户决策**（影响面：前端契约与 413 处 fastjson2 调用点）。
