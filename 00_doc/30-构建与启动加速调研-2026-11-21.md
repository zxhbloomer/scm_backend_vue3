# 构建与启动加速调研（wayfinder map #1 研究票汇总）

日期：2026-11-21　｜　对应 map：[Map：SCM 后端构建与启动加速](../)（GitHub issue #1）
研究票：#2 mvnd、#3 热重载、#4 build cache、#5 启动加速、#6 模块结构

## 一、问题

开发后台用命令行完成「改代码 → 编译 maven 多模块 → 打包 → 启动」，单次反馈要等很久。要找出真正能压缩耗时的环节。

## 二、现状体检（本轮实测，非推测）

| 项 | 实测值 | 出处 |
|---|---|---|
| 模块数 | 25 个有效 `<module>`，另 4 个已注释 | `pom.xml` |
| 源码规模 | 3352 个 `.java`（不含 `00autoCreateCode`） | `find` 统计 |
| 体量集中在 | `scm-bean` 1165、`scm-core` 1053、`scm-ai` 274、`scm-common` 146、`scm-controller` 145 | 同上 |
| 空/薄模块 | `scm-controller-api` 0、`scm-controller-tenant` 1、`scm-start` 1、`00autoCreateCode` 1 | 同上 |
| 打包产物 | `scm-start/target/scm-start-0.0.1-SNAPSHOT.jar` = **337M**；`scm-core` jar 2.1M | `ls -lh` |
| 构建环境 | `JAVA_HOME=D:\2025_project\99_tools\jdk\jdk-21.0.8`；`MAVEN_OPTS` 空 | 环境变量 |
| 构建加速配置 | 无 `.mvn/jvm.config`、无 `.mvn/maven.config`、无 `mvnw` | 目录检查 |
| 热重载 | `spring-boot-devtools` 在 10 个 pom 里被**注释掉** | `grep spring-boot-devtools` |
| 本地仓库 | `~/.m2/repository` 89M，`settings.xml` 配了 1 个 mirror | 磁盘检查 |

结论：慢的主因大概率不是「Maven 本身」，而是 ① 每轮都跑全 reactor ② 每轮都打 337M 胖 jar ③ 没有热重载、每改一行都 cold start ④ JVM/插件类没有跨次复用。

## 三、候选方案（每条：收益 / 代价 / 回滚）

| # | 方案 | 收益量级 | 代价 | 回滚 |
|---|---|---|---|---|
| 1 | **跳过本地 repackage**：`-Dspring-boot.repackage.skip=true`（本地开发不产胖 jar） | 单次省掉 337M 重打包，**量级最大的一刀** | 无（CI/发版仍照常打） | 去掉参数 |
| 2 | **mvnd 替代 mvn**（Apache Maven Daemon 1.0.6，内嵌 Maven 3.9.x） | 常驻 daemon 复用 JVM + 插件类加载器 + JIT 代码，二次构建显著变快；官方默认已按 `核数-1` 并行 | 需装一个二进制（Windows x86_64 受支持，Temurin/Liberica/Zulu/MS JDK 17/21/25）；多一个常驻 JVM 占内存 | 直接改用 `mvn` |
| 3 | **devtools 重启**（打开注释，仅 dev 生效） | 只重启变更类所在的 restart 类加载器，比 cold start 快一个量级；官方推荐先用它 | 会话状态/定时任务/MQ 消费者会随重启丢；大改了才划算 | 去掉依赖 |
| 4 | **IDE 内跑 `SystemServerStart`**（IDE 增量编译） | 编译粒度细化到「改的类」，彻底绕开 reactor | 依赖 IDE，命令行场景不覆盖 | 回 CLI |
| 5 | **Maven Build Cache Extension 1.3.0** | 按模块指纹跳过未变更模块，25 模块 reactor 收益明显 | 引入扩展 + 本地缓存目录；`clean` 后失效；对打包类目标收益不确定 | 移除扩展声明 |
| 6 | **CDS / AppCDS** | 冷启动省几秒（类加载） | 要生成并分发归档，dev 收益小 | 删参数 |
| 7 | **懒加载 `spring.main.lazy-initialization`（仅 dev）** | 启动变快 | 首次访问某接口才初始化，报错推迟、排查变难 | 关掉开关 |
| 8 | **CRaC / 换 JDK 发行版** | 快照恢复近乎瞬时 | **CRaC 基于 CRIU，官方文档明确是 Linux**；本机是 Windows，本地开发不可用；还要换 JDK | 不引入 |
| 9 | **HotswapAgent + DCEVM/JBR** | 真热替换，不重启 | 与 Spring AOP/CGLIB/Lombok 的组合坑多，需专门 JDK | 卸插件 |
| 10 | **模块治理**：`00autoCreateCode` 从 reactor 摘出、`-pl scm-start -am` 只编必要子集 | 少编 1~2 个模块 | 需要有人记住正确命令 | 恢复模块 |

## 四、建议（按性价比排序）

1. **先做 1 + 3**：本地命令固定成 `mvn -pl scm-start -am package -DskipTests -Dspring-boot.repackage.skip=true`，dev 打开 devtools 重启。改一行到生效从「分钟级等待」降到「秒级等待」，零架构风险。
2. **再做 2**：装 mvnd，把日常命令全部换 `mvnd`，命令行交互体验（并行输出、常驻）一并收益。
3. **按需 5**：如果团队里 CI 也走同一台机器/同一条命令，再评估 build cache；本地内循环已经够快时不必上。
4. **不做 8**（Windows 上 CRaC 不可用）、暂不做 9。
5. **7 只在启动确实痛时试**，且只允许 dev profile。
