### A3 · 升级窗口能否清空 Redis 业务缓存并排空 RabbitMQ 在途消息？

| 项 | 内容 |
|---|---|
| 为什么要问 | 存量 Redis 值是 Jackson 2 序列化的；`RedisSerializer.json()` 换成 Jackson 3 后官方明确"输出可能不同，需继续用旧序列化器读存量直到迁移完成"。这是不可绕过的数据面断裂 |
| 选项 | ① 可停机、可清、可排空（最干净）② 不能清，需双读兼容层（+5–8 人日 + 长期技术债）③ Session 不能丢（用户不能掉线） |
| 我的建议 | ①；若③成立，则 `spring-session` 的序列化器本轮不动，只升业务缓存 |
| 不确认的后果 | 默认按①做方案；若实际②，工作量需重排 |

### A4 · `ACT_RU_VARIABLE` / `ACT_HI_VARINST` 里 748 条 `wms.*` 序列化变量怎么办？（2026-10-28 已给真实样本与实测结果）

| 项 | 内容 |
|---|---|
| 事实 | 这些变量的 `serializable` 类型指向的类（如 `wms.Form`）**在当前代码里已不存在**（wms→scm 改包名），任何读取都会 `ClassNotFoundException`。升级前就存在的存量缺陷，升级会把它从"潜在"变"必然" |
| 选项 | **a 归档**：导出后删除这些行（历史详情丢失但能跑）<br>**b shim**：写 `resolveClass` 兼容映射把老类名映射到现有类（保数据，需知道原类结构）<br>**c 转 JSON**：一次性把 `serializable` 转成 `json`（最彻底、工作量最大） |
| 我的建议 | **b**，若能确认原类字段；否则 **a** |
| 不确认的后果 | 上线后凡碰到这些实例的查询/审批会抛异常 |
